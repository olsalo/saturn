# Implementation decisions

- Tauri 2, React, TypeScript, Tailwind 4. One native window morphs between capture and export. The browser dev server previews the UI; capture requires the desktop runtime.
- Coss UI installed manually from its published registry sources, with only Button, Menu, Switch, Progress and the Button's Spinner dependency in `src/components/ui`. Import paths were adapted to this repository. No shadcn initializer or full UI library install.
- macOS 15+ native Swift capture bridge is statically linked into Saturn by `build.rs`. Permission checks, window enumeration, the system picker and recording execute inside the app process. A separate Swift sidecar remains for AVFoundation/Core Animation export, media inspection and Finder/clipboard actions. Rust exposes narrow commands, without frontend shell permissions or an FFmpeg distribution dependency.
- Production capture uses a custom searchable window list after explicit Screen Recording consent. Window IDs are resolved again against current ScreenCaptureKit content before recording. Following Recordly v1.4.0, a display filter excluding Saturn is cropped to the window bounds with `sourceRect`; no system content-sharing picker or single-window filter is used. This avoids window-sharing controls at the cost of capturing any overlapping content in the selected area. The crop follows move/resize on one display, with fixed even output dimensions, and stops/finalizes on closed, minimized or off-display windows. macOS 15+ is required.
- Cursor movement is polled continuously at 30 Hz on a serial capture queue, including when ScreenCaptureKit emits no complete frames for static content. Observations use the host clock relative to the first complete frame PTS, rather than stamping current positions with an older frame-delivery timestamp. Export interpolates recorded positions without low-pass delay; gaps over 100 ms and visibility transitions hold the previous point. Fixed capture dimensions define the coordinate mapping as crops move/resize. Cursor timers are stopped and drained before closing metadata. Direct recording output may use a slightly different start origin; precise live synchronization remains an interactive release check.
- Click bounce uses Core Graphics mouse-down counters and event age sampled with cursor observations, without an event tap or new Accessibility/Input Monitoring request. A 240 ms pulse compresses the cursor by 10%, rebounds by 3%, and settles around the unchanged hotspot. New recordings enable clickAnimation; older recordings without click metadata remain unchanged. Audio toggles are explicit; system audio defaults on, microphone off.
- Rust owns validated archives, workspaces, jobs, progress delivery, atomic saves and native file dialogs. The frontend gets metadata and scoped still-image URLs; no video frames cross IPC. Native output progress reflects AVFoundation encoding, with completion only after a validated file is committed.
- Appearance controls auto-save after an intentional selection. Export does not repack a clean project. If a project has moved or disappeared while open, Save As is required to preserve edited settings.
- The minimum macOS version, source filter behavior, permissions identity in a signed bundle, pointer time alignment, and long recording behavior remain release gates. Windows adapters, signing/notarization and broad hardware testing are not provided by this initial macOS implementation.

- Recording and staging workspaces use owner-only directory permissions on Unix. Clean staging caches are removed at startup; dirty sessions are retained. Capture attempts to finalize media even after an unexpected stream stop and reports a saved-recovery warning when usable footage remains.
- Disk-space preflight checks the full archive copy before save/open, a small reserve before capture, and a conservative two-times-source-size estimate before export. Running out of space later still fails without replacing a prior successful file.

- The normal `npm run desktop` command opens the existing signed debug `.app` through LaunchServices, building it only when absent. `npm run desktop:build` explicitly rebuilds with the `custom-protocol` feature. A raw `tauri dev` launched from VS Code was observed in TCC logs as requesting Screen Recording under VS Code, even after Saturn had been approved. Hot reload remains available as `desktop:dev`. Selection opens only on an explicit picker action. The app does not modify privacy settings. The launcher uses the supported `tccutil reset ScreenCapture com.saturn.recorder` command when a remembered designated signing requirement changes or an explicit repair is requested; it never edits the TCC database directly or grants permission.

- Local bundles explicitly use Tauri's ad-hoc signing (`signingIdentity: "-"`). Without this setting the packaged executable retained its linker's generated Rust identifier, had no bound Info.plist, and did not match the app identity approved for screen capture. The launcher verifies the complete signature, the `com.saturn.recorder` identifier and Info.plist binding before opening it. The current window-list flow requires persistent global Screen Recording permission; ad-hoc permission persistence still requires interactive validation.

- Normal launches preserve the signed app unchanged and activate an existing instance instead of using `open -n`. Building/signing on every launch risks invalidating ad-hoc consent and creates duplicate panels whose process state can differ. Code updates are applied only with the explicit `desktop:build` command.

- Saturn hides its visible panel while recording and excludes its process from the display filter. A native menu-bar Stop item ends recording and restores the panel on completion or failure. Permission checks are passive; requesting access and opening Settings are explicit user actions. Rejected ScreenCaptureKit sessions block automatic retries, preventing repeated permission dialogs.
- A small C ABI carries JSON events from Swift to Rust workers. Task-local reporters separate concurrent calls, serialize callbacks and close before returning, so delayed native callbacks cannot access released Rust state. AppKit and the system picker stay on the main actor while capture coordination stays off the UI thread.

- The launcher persists the last designated signing requirement beside the debug bundle. A changed requirement triggers a Saturn-only Screen Recording reset after confirming the app is stopped; the new identity is remembered only after the reset succeeds. Ordinary launches and matching certificate signing requirements preserve consent. `desktop:repair` provides the same scoped recovery for an already-stale approval without rebuilding. The final macOS approval remains a user action.

- Window-area crops align inward to the display's physical-pixel grid and trim the outermost native border pixel. Even encoded dimensions match the source rectangle exactly. Cursor transforms use this actual crop frame. The export shadow uses a shadow path without a solid black fill behind the video, preventing that fill from bleeding at antialiased mask edges.
- Cursor appearance uses `NSCursor.currentSystem` on the main actor, the same system source used by Recordly's native cursor monitor. Actual PNG images, logical dimensions and hotspots are stored portably, including custom cursors; no heuristic role-based shape substitution or new Accessibility/Input Monitoring permission is needed. Export renders 1.75× native size around each hotspot, switches image discretely, and clips sprites to the video's rounded mask. Existing recordings without shape metadata use the native arrow.

- The export canvas is 1920×1200 at 30 fps. `paddingPercent: 38` follows Recordly's linked slider mapping (setting ÷ 100 × 0.2), creating 7.6% insets independently on each canvas axis. Preview and native compositor share this math and fit the source without changing its aspect ratio. Old manifests remain readable; projects opened in the app adopt the current export layout in their staged manifest.
- The public asset bundle contains all 38 Recordly v1.4.0 JPEG wallpaper images, copied byte-for-byte with verified Git blob hashes, plus lightweight gallery thumbnails and the upstream license. The native preset command allowlists IDs from the shared catalog, reads the already-bundled frontend image, checks JPEG magic/size, and embeds it in the project. No duplicate native resource collection or runtime download is needed.

- Export duration is bounded by actual picture samples rather than container duration. AVSampleCursor locates the last sample with picture payload, skipping empty ScreenCaptureKit end markers; a compressed-sample reader is the fallback for formats without sample cursors. The end is rounded down to a complete 30 fps boundary, audio is intersected with the same range at its original offset, and exporter/instruction/animation ranges agree. The actual final encoded frame must decode before an MP4 can be committed. No pixel-brightness heuristic removes legitimately dark content; original source footage is preserved.

- Final compression uses bundled official HandBrakeCLI 1.11.2 with its Fast 2160p60 4K HEVC preset, software x265 10-bit/RF 24/faster, plus `--optimize` for MP4 fast start. Cropping, anamorphic resizing and interlace filters are disabled for the already-composited progressive canvas; all audio tracks are retained as AAC. The 16:10 canvas is 3456×2160, within 3840×2160 preset limits; source frame rate is retained up to 60 fps. Original capture remains native-resolution H.264 MOV.
- AVFoundation produces a temporary ProRes 422/LPCM master so final quality is controlled by x265 rather than a generic native export preset. Explicit Rec.709 primaries, transfer function and matrix preserve source colors through the master. Temporary disk reservation is based on pixel count, source fps and duration, with cleanup on every exit. Encoder output is drained concurrently, progress covers both phases, and cancellation terminates a running encoder without committing output.
- `setup:encoder` pins archive and executable SHA-256 checksums, downloads only from the official HandBrake release, mounts it read-only, and copies the universal CLI under the host sidecar name. The normal build runs this preparation automatically. License and source notices are maintained under `public/legal/handbrake/` for bundling with the app.

- Compact exports (2026-11-08): retain the 4K ProRes compositor master, then downscale final MP4s to at most 1920×1200/30 fps. Use two-pass x265 Main 10 with the slow preset and a 240 kbit/s combined bitrate budget (64 kbit/s per retained AAC stereo track). This targets under 1 MB per 30 seconds, with MP4 overhead headroom, at the cost of export time and some fine detail. Keep the tested Apple Silicon SIMD workaround and edge options. Existing recordings and project geometry remain intact.
- Higher-resolution compact exports (2026-11-08): raise the final export cap from 1920×1200 to 2880×1800 after user review. Keep the bitrate budget and artifact workaround. The repeated real-footage 30-second sample remains under 1 MB at 745,693 bytes, with all 900 frames passing the black-patch regression.
- Final compact-export settings (2026-11-08): use the user-requested 2720×1700 (16:10). Protect faint window-control outlines using edge-aware AQ, 8-pixel quantization groups, psy-rdoq 1.0 and I/P ratio 1.6; retain the budget and SIMD workaround. Original source/master comparisons established that the reported cut-off buttons were compression loss. The 30-second export is 759,303 bytes and passes both outline and black-patch regressions. AQ mode/group semantics are documented in the [x265 options reference](https://x265.readthedocs.io/en/4.1/cli.html#cmdoption-aq-mode).

- Quality and export speed (2026-11-08): use 2560×1600 throughout compositing and encoding, with a 30 fps ceiling. Replace the 240 kbit/s budget and two slow bitrate passes with RF 18 constant quality and the faster x265 preset. Preserve edge-aware AQ and the tested Apple Silicon SIMD workaround. Retain all audio tracks at 128 kbit/s AAC stereo. File size follows content complexity; the previous under-1-MB target no longer applies. Legacy projects adopt this layout with proportional corner radii.

- FFmpeg is the default macOS final encoder (`ffmpeg`), using hardware VideoToolbox HEVC Main 10 at quality 57, a 30 fps ceiling, all audio tracks as 128 kbit/s AAC stereo, and MP4 Fast Start. The former HandBrake hardware (`videotoolbox`) and x265 (`handbrake`) paths remain explicitly selectable with their previous options. Hardware availability is probed before compositing; no implicit backend fallback is performed. A pinned, checksum-verified FFmpeg 8.0.1 source release builds a separate minimal LGPL CLI using only system frameworks. The complete source archive, license and build instructions accompany the frontend assets. Recording/compositing remains macOS-only.

- FFmpeg's hardware export explicitly uses `-g 301 -bf 2` and `-aac_at_mode cvbr`: the initial migration inherited a twelve-frame GOP and constant-rate audio, unlike HandBrake. The former repeatedly re-encoded static UI; the latter padded silence. Keep the 57 quality setting and 128 kbit/s audio target while matching HandBrake's roughly ten-second GOP at 30 fps and allowing constrained-variable audio.
