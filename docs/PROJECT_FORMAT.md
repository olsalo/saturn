# Saturn project format, version 1

A `.saturn` file (formerly `.recproj`, still accepted when opening) is a ZIP64 archive using STORE (no compression). `manifest.json` references `media/source.mov` or `media/source.mp4`, `cursor/events.jsonl`, an optional `cursor/assets.json` native-cursor bitmap registry, and an optional `assets/background.jpg` or `.png`. A JPEG thumbnail may be included at `preview/thumbnail.jpg`. All archive references are relative and restricted to these paths. No absolute source or destination paths enter the portable document.

The manifest implements the architecture document's version 1 schema. Supported backgrounds are `none`, `gradient` with `dawn`, `dusk`, `mint`, or `ink`, and `embeddedImage`. Cursor events contain monotonic integer `tUs`, `type: "move"`, finite `x`/`y` coordinates in source pixels and a `visible` boolean. Capture polls cursor movement at 30 Hz independently of screen-content updates, using host-clock observations relative to the first video PTS. Capture also writes the current Quartz bounds in a `transform` object for diagnostics. Export uses timestamp-preserving interpolation, holds across missing-data gaps over 100 ms and visibility changes, and adds no low-pass position delay. Older projects can contain long cursor gaps; missing trajectories cannot be reconstructed. New cursor events optionally carry a `cursorID` plus `cursorScaleX`/`cursorScaleY` (screen points to source pixels). `cursor/assets.json` maps IDs to base64 PNG data, native point dimensions, and top-left hotspot coordinates. The registry is optional for old projects; their missing shape data falls back to the macOS arrow. Native system images are captured via `NSCursor.currentSystem`, and export scales sprites to 1.75× native size around the recorded hotspot. Shapes switch discretely at recorded timestamps; position interpolation remains independent. The registry is limited to 256 assets and 16 MiB. New captures enable `clickAnimation` by default. Optional `click: true` and `clickUs` on movement samples mark a detected mouse-down and its estimated capture-relative timestamp. Event counters catch clicks even when a button was released between polls. `clickUs` is bounded by its observation timestamp. Click bounce scales around the hotspot for 240 ms (10% press, 3% rebound), with overlapping clicks combined smoothly. Older projects without click observations render without bounce.

Output defaults to web-optimized MP4/HEVC Main 10 with a 30 fps ceiling. Window captures default to 16:10 and High; display captures default to their source aspect ratio and Original resolution. Window captures offer Original, 16:10, 16:9, 9:16 and 1:1 canvas aspect ratios; display captures retain the source aspect ratio. Window recordings also use the source aspect ratio when the background is set to None, restoring the selected canvas shape when a background is added again. Original, High, Medium and Small resolution choices set the canvas pixel dimensions to 100%, 90%, 75% and 60% of a base canvas. The base fits the chosen aspect ratio within the source long and short dimensions and a 4096-pixel per-side cap; the source is not upscaled. Dimensions are rounded down to even pixels. FFmpeg uses VideoToolbox HEVC Main 10 at quality 57 after a temporary ProRes 422/LPCM compositor master at the final resolution. Quality determines file size; there is no fixed bitrate or file-size budget. New recordings store system and microphone audio separately in optional media/system.m4a and media/microphone.m4a files, with offsets relative to the video; export mixes the enabled sources into the video. Older recordings keep their original mixed audio, which cannot be separated later. The temporary master is not archived and is deleted after success or failure. The reader also accepts legacy H.264, 60 fps and 1280×720/1920×1080/1280×800/1920×1200/3456×2160 export manifests. App-opened projects preserve their canvas selections; older projects default to 16:10 and High, while display captures retain their source aspect ratio. `appearance.paddingPercent: 38` matches Recordly’s linked padding: a 7.6% inset on each canvas edge, computed independently from width and height. The source fits inside the remaining area without distortion. Older files may omit `paddingPercent`; standalone rendering retains their `paddingPx` fallback. Selecting a bundled wallpaper copies its full image to `assets/background.jpg` and records an optional `background.preset` ID; the embedded file is authoritative and travels with the project. Original video/audio stays unchanged. Current media limits: 24 hours, 16384 pixels per dimension, one source file up to 64 GiB, 512 MiB cursor metadata, 32 MiB per image, 64 KiB manifest, and 3 million cursor samples. Unknown archive paths, duplicates, symlinks, compressed/encrypted entries, malformed cursor events, invalid checksums, and future versions are rejected. These are implementation safety limits, not measured performance guarantees.

Saves stream a replacement archive into a unique file beside the destination, sync it, rename it atomically, and sync the containing folder. Failed saves leave the original archive and recoverable workspace intact. Appearance changes are committed after each explicit background selection; no sliders continuously repack the source. Export reads the workspace, writes an adjacent temporary MP4, validates it with AVFoundation, syncs it, and renames only on success.

The app support `sessions/` folder holds staged media, `manifest.json`, a `dirty` marker for unsaved work, and `recovery.json` with the user's destination. These are temporary recovery records, not a project database. Clean staged sessions are removed when switching projects or starting a new recording. A crash during capture leaves the source and cursor file for an explicit recovery attempt. A MOV interrupted before its container finalizes may be unrecoverable; such data is retained rather than discarded.

MP4 duration is bounded by real video samples and rounded down to complete output frames; the original source duration in the manifest remains unchanged. Empty terminal samples and audio-only tails do not extend the rendered video. Audio keeps its original timeline offset and is trimmed to the export range. Successful export requires decoding the final output frame.
